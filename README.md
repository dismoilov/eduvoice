# EduVoice — AI-оператор call-центра Министерства высшего образования

Голосовой помощник, который отвечает на звонки граждан **на узбекском языке**: слушает
вопрос, отвечает по регламентам, а всё, в чём не уверен, переводит на живого оператора.

Работает на связке **FreePBX/Asterisk** (телефония) + **VoiceLab.uz** (речь и модель,
узбекские сервисы, данные не покидают Узбекистан) + собственный мост на Python.

> Задачи из перечня хакатона: **№5** — автоматизация call-центра Министерства высшего
> образования с распознаванием и синтезом узбекской речи, и **№3** — ответы строго на
> основе нормативных документов.

ключей остаётся режим заглушек (`EDUVOICE_PROVIDER=fake`) — на нём работают все тесты.

## Как это работает

```
   Звонок                  Asterisk / FreePBX                        Мост (Python)
     │                            │                                        │
     ├── 7000 ──────────────────►│                                        │
     │                    [eduvoice-ai]                                    │
     │                     1. создаёт UUID звонка                          │
     │                     2. POST /calls/{uuid}/start ──────────────────►  регистрация
     │                     3. MixMonitor — запись разговора                │
     │                     4. Dial(AudioSocket/…) ═══ звук 8 кГц ═══════►  диалог
     │ ◄═══════════════════════ звук ответа ═══════════════════════════════╡
     │                     5. GET /calls/{uuid}/next ───────────────────►  решение
     │                            │                                        │
     │                     «hangup» → положить трубку                      │
     │                     иначе   → [eduvoice-operators] очередь операторов   │
```

Внутри моста один звонок проходит по конечному автомату
`greeting → listening → thinking → speaking → closing`:

1. **listening** — звук режется на кадры по 20 мс, детектор речи (webrtcvad) ловит начало
   и конец фразы: 3 «речевых» кадра из 5 — начало, 700 мс тишины — конец.
2. **thinking** — фраза уходит в распознавание, затем текст — в правила и модель.
   Если ответ не готов за 1.2 с, звучит «Bir daqiqa, tekshiryapman».
3. **speaking** — ответ синтезируется и отдаётся ровно по кадру в 20 мс (иначе Asterisk
   «проглотит» речь). Всё это время слушаем человека: заговорил — замолкаем.
4. **closing** — прощальная фраза, решение записывается для диалплана, сокет закрывается.

Главный инвариант: **человек никогда не остаётся в тишине**. Любая ошибка — недоступный
провайдер, непонятый вопрос, упавший мост, оборванный сокет — заканчивается переводом на
оператора. Решение «что делать дальше» записывается *до* всего, что может упасть, а
диалплан по умолчанию отправляет звонок человеку.

Подробный разбор архитектуры и принятых решений — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Структура проекта

```
eduvoice/                мост: один модуль — одна ответственность
  main.py             точка входа: AudioSocket-сервер, control API, панель
  session.py          логика одного звонка (конечный автомат)
  audiosocket.py      протокол Asterisk AudioSocket, ровный вывод звука
  vad.py              границы фразы и перебивание
  audio.py            PCM: ресемплинг, нарезка на кадры
  brain.py            решение по вопросу (правила + модель)
  content.py          FAQ из content/faq.yaml
  prompts.py          служебные фразы и их кэш
  registry.py         состояние звонков
  control_api.py      HTTP для диалплана (три ручки)
  calllog.py          журнал звонков в JSON
  config.py           все настройки в одном месте (.env)
  interfaces.py       контракты провайдеров речи и модели
  fakes.py            заглушки провайдеров
  voicelab.py         VoiceLab.uz: распознавание, синтез с кэшем, модель
  voice_tools.py      озвучить фразу, наполнить кэш (prewarm)
crm/                  CRM: рабочее место call-центра (FastAPI + Jinja2)
  app.py              сервис, маршруты, обработка ошибок
  repo.py             все запросы к базе в одном месте
  stats.py            цифры рабочего стола и аналитики
  security.py         пароли, сессии, защита форм
  views/              экраны: звонки, обращения, граждане, база знаний, аналитика
  templates/          страницы (серверный рендеринг, без сборки)
  static/             оформление и небольшой скрипт плеера
store/                общая база данных моста и CRM (SQLite)
asterisk/             диалплан — исходник правды, деплоится на сервер
content/              тексты: FAQ и служебные фразы (узбекский)
deploy/               systemd-юниты моста и CRM
docs/                 документация (см. ниже)
tests/                238 тестов
```

## Быстрый старт

```bash
make install          # окружение (Python 3.12, uv)
make check            # линтер + тесты
make deploy           # выкатить мост на сервер и перезапустить
make deploy-dialplan  # выкатить диалплан и перечитать его
```

Проверка без телефона — звонок генерирует сам Asterisk:

```bash
make say TEXT="operator bilan gaplashmoqchiman"  # что «услышит» заглушка
make agent-on                                    # подставной оператор
make call-test                                   # звонок с вопросом после приветствия
make calls                                       # журнал: вопрос, решение, задержки
```

CRM — записи разговоров, вопросы и ответы помощника, обращения, аналитика:

```bash
# открыть http://10.103.10.86:9095 (логины и пароли — в /root/eduvoice-credentials.txt)
make sql Q="select count(*) from calls"          # заглянуть в базу
make voice-prewarm ARGS=--dry-run                # что осталось озвучить и почём
```

## Качество кода

```
238 тестов                 uv run pytest -q
линтер, формат, типы      ruff + mypy (make lint)
```

Тесты не требуют ни телефона, ни ключей: есть сквозной тест, который проигрывает
настоящий звонок через TCP-сокет ровно так, как это делает Asterisk
([tests/test_end_to_end.py](tests/test_end_to_end.py)), и отдельный набор тестов на
отказы — каждый отвечает на вопрос «может ли человек остаться в тишине?»
([tests/test_session_failures.py](tests/test_session_failures.py)).

## Как заменить поставщика речи

Весь мост знает о распознавании, синтезе и модели только то, что написано в
[eduvoice/interfaces.py](eduvoice/interfaces.py). Поэтому VoiceLab подключается одной
строкой `EDUVOICE_PROVIDER=voicelab`, а заглушки — `fake`; код диалога при этом не
меняется вообще. Разбор того, чем живой API отличается от своей документации, —
в [docs/VOICELAB-TASKS.md](docs/VOICELAB-TASKS.md).
