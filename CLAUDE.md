# EduVoice — контекст проекта для ИИ-ассистента

Этот файл — точка входа для любой модели, которая открывает репозиторий впервые.
Claude Code читает его автоматически; другому ассистенту его достаточно дать целиком.
Всё написанное ниже проверено на живом сервере, а не предполагается.

Дата последней правки: 18.09.2026.

---

## 1. Что это

**EduVoice** — голосовой ИИ-оператор call-центра Министерства высшего образования
Узбекистана плюс CRM для сотрудников. Делается на хакатоне «Umummilliy AI Xakaton»
(Хорезм, 17–20.09.2026), задачи №5 (автоматизация call-центра с узбекской речью) и
№3 (ответы строго по нормативным документам).

Человек звонит → узбекское IVR → ассистент слушает, распознаёт, отвечает по регламенту
или переводит на живого оператора → разговор, расшифровка и решение попадают в CRM.

Команда: **человек A** (пользователь) — телефония, мост, диалог, CRM. **Человек B** —
модуль VoiceLab (речь и модель), задание в `docs/VOICELAB-TASKS.md`.

## 3. Как всё устроено

```
Звонок → Asterisk (7000) → [eduvoice-entry] IVR → [eduvoice-ai]
                                 │ POST /calls/{uuid}/start          (HTTP 9093)
                                 │ MixMonitor → запись .wav
                                 │ Dial(AudioSocket/127.0.0.1:9092/{uuid})  ← звук 8 кГц
                                 │ GET /calls/{uuid}/next → operator | hangup
                                 ▼
                       мост eduvoice-bridge (Python)
                                 │ пишет звонок, реплики, гражданина
                                 ▼
                    SQLite /opt/eduvoice/data/eduvoice.db  (WAL)
                                 ▲
                                 │ читает всё, правит; публикует ответы
                       CRM eduvoice-crm (FastAPI, порт 9095)
```

Два процесса намеренно раздельны: перезапуск CRM не может уронить разговор. Общий у них
только файл базы. Мост читает из базы **только опубликованные** ответы, не чаще раза в
10 секунд.

## 5. Инварианты — не нарушать

1. **Звонящий никогда не остаётся в тишине.** Любая ошибка → перевод на оператора.
   Решение для диалплана пишется в реестр **до** всего, что может упасть; control API на
   неизвестный звонок отвечает `operator`; диалплан использует `Dial(AudioSocket/…,,g)`,
   а не приложение `AudioSocket()` (оно кладёт трубку при падении моста).
2. **Модель не распоряжается звонком.** Она возвращает только JSON с intent; что делать —
   решают правила в `brain.py`. Выдуманный `faq_id` не озвучивается, модель не может сама
   положить трубку.
3. **Черновик ответа не попадает к гражданину.** Мост читает только `status='published'`.
4. **Форматы звука зафиксированы:** телефония 8 кГц, распознавание 16 кГц, синтез 24 кГц;
   пересчёт делает мост, провайдеры его не касаются.
5. **Ошибки провайдеров** приходят как `SttError`/`TtsError`/`LlmError`, иначе мост падает.
6. **Секретов в репозитории нет.** Всё в `.env` на сервере (права 600) и в
   `/root/eduvoice-credentials.txt`.
7. **Перед выкладкой — зелёные тесты:** `make deploy` сам запускает `make check`.

## 6. Решения и их причины (не «чинить» обратно)

| Решение | Причина |
|---|---|
| AudioSocket, а не ARI | нужен только звук; AudioSocket встроен в Asterisk 20 |
| `Dial(AudioSocket/…)` вместо `AudioSocket()` | проверено: при падении моста звонок переживает и уходит оператору |
| webrtcvad | единственный VAD, который ставится на Sangoma Linux 7 (glibc 2.17) |
| numpy<2.3, soxr<1 | нет колёс под glibc 2.17 |
| SQLite (WAL) | одна машина, нужны транзакции и поиск; FTS5 для расшифровок |
| CRM на FastAPI + Jinja2, серверный рендеринг | десятки форм; никакой сборки и npm — на защите может не быть интернета |
| control API без зависимостей | три ручки, а новые колёса на старом сервере — риск |
| Пароли `hashlib.scrypt`, сессии `hmac` | стандартная библиотека, нечего ставить |
| Плоская раскладка пакетов | при `src/` uv периодически терял модуль |
| Ответы живут в базе, а не в YAML | супервайзер правит текст без программиста |

## 9. Как проверять, а не гадать

- **Живой звонок:** `make say TEXT="stipendiya qanday olinadi"` → `make call-test` →
  `make logs` (видно `heard`, `decision`, задержки) → CRM → Звонки.
- **База:** `sqlite3` на сервере нет, используй
  `uv run --no-sync python -c "import sqlite3; ..."` в `/opt/eduvoice/app`.
- **CRM снаружи:** `curl -s -c jar -d "login=nazorat&password=…" http://10.103.10.86:9095/login`,
  дальше с `-b jar`.
- **Отказоустойчивость:** остановить `eduvoice-bridge` во время звонка — звонок обязан
  уйти в очередь операторов.
- **Скриншоты интерфейса:** локально поднять CRM и снять headless-браузером — так уже
  ловились ошибки вёрстки, которых не видно в HTML.

## 10. Соглашения

- **Комментарии и docstring в коде — по-английски**, документация и общение с
  пользователем — по-русски, интерфейсы для людей — узбекский + русский.
- Узбекская орфография: `oʻ`/`gʻ` — U+02BB, tutuq belgisi — U+02BC. В `pyproject.toml`
  они внесены в `allowed-confusables`, менять на апострофы нельзя.
- **`javob` по-узбекски значит «ответ»** — это слово встречается в текстах ассистента и в
  подписях CRM. Не переименовывать: проект назывался Javob до 18.09, но теперь EduVoice
  только там, где это идентификатор.
- Тесты пишутся так, чтобы падать на сломанном коде: у каждого — конкретный сценарий
  отказа, а не «функция вернула что-то».
- Пользователь просил: проверять каждый шаг вживую, не изобретать факты, не торопиться с
  гитом, интерфейсы делать непохожими на типовые ИИ-шаблоны.
