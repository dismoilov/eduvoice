## Правила работы

1. Перед каждой выкладкой на сервер: `make check` (линтер + тесты). Красное — не выкладываем.
2. Каждый шаг заканчивается **проверкой из таблицы**, её результат вставляем в колонку «Проверено».
3. Провайдеры (распознавание, синтез, LLM) всегда за интерфейсами из `eduvoice/interfaces.py`. Пока работает `fake`, переключение на VoiceLab — одна переменная в `.env`.
4. Ничего секретного в репозиторий: ключи только в `.env` (он в `.gitignore`), пароли сервера — в `/root/eduvoice-credentials.txt`.
5. Любое изменение плана набора Asterisk дублируем в `asterisk/extensions_custom.conf` в репозитории, чтобы не потерять.

## Проверки после каждого шага (детально)

**A2. Звук**
- Тон 440 Гц, 1 с: 8000 → 16000 → 8000 даёт ту же длительность ±1 мс.
- Нарезка 1 с на кадры: ровно 50 кадров по 320 байт.
- Остаток меньше кадра сохраняется до следующего вызова, ничего не теряется.

**A3. AudioSocket**
- Разбор кадра: тип, длина, данные. Кадр 0x01 (UUID) превращается в строку UUID.
- Сборка: любой набор данных режется на кадры 0x10 по 320 байт.
- Ритм отправки: 50 кадров за 1 с ± 30 мс.
- Очистка очереди: после `clear()` следующий кадр уходит уже из нового текста.
- На сервере: `make originate-test` → в логе число кадров ≈ длительность × 50.

**A4. Конец фразы**
- Тишина не считается речью.
- Тон 440 Гц считается речью (тест на webrtcvad может быть нестабилен — тогда берём записанные фразы).
- После записи «вопрос + 1 с тишины» конец фразы найден в пределах 0,6–0,9 с после конца речи.

**A6. Управление**
- `curl -d 'caller=998901234567&lang=ru' localhost:9093/calls/<uuid>/start` → `ok`.
- `curl localhost:9093/calls/<uuid>/next` → `hangup` или `operator`.
- Неизвестный uuid → `operator` (безопасное поведение).
- `curl localhost:9093/health` → JSON.

**A7. Диалог**
- В логе по очереди: `greeting → listen → transcribe → think → speak → listen`.
- Молчание 6 с → переспрос, ещё 6 с → прощание.

**A8. Перебивание**
- Во время ответа подаём речь → в логе `barge-in`, отправка звука прекращается за ≤ 0,5 с.
- Эхо собственного голоса не вызывает ложных срабатываний (проверяем на живом звонке).

**A10–A11. Живые проверки**
- Софтфон 101 → 7000 → вопрос → ответ.
- «Operator» → звонит 200.
- `systemctl stop eduvoice-bridge` во время звонка → звонок уходит оператору.

## Журнал решений

| Дата | Решение | Причина |
|---|---|---|
| 17.09 | Телефония FreePBX + AudioSocket, мозг в отдельном процессе | AudioSocket есть в Asterisk 20.4, DTMF и переменные канала через него не передаются |
| 17.09 | Управление звонком через `CURL()` из плана набора | ARI требует Stasis, а так проще и надёжнее |
| 17.09 | VAD — `webrtcvad` | onnxruntime (Silero) не ставится на glibc 2.17 |
| 17.09 | numpy < 2.3, soxr < 1 | Нет сборок под glibc 2.17 |
| 18.09 | Плоская раскладка `eduvoice/` без сборки пакета | При раскладке `src/` editable-режим uv периодически терял модуль |
| 18.09 | Входящий звук режем на кадры 20 мс перед VAD | Asterisk иногда присылает куски другого размера, webrtcvad принимает только 10/20/30 мс и падал |
| 18.09 | `Dial(AudioSocket/...)` вместо приложения `AudioSocket()` | Проверено на сервере: при падении моста посреди звонка приложение кладёт трубку, `Dial` с опцией g продолжает план и уводит звонок оператору |
| 18.09 | Только узбекский язык, IVR тоже | Решение команды: меню выбора языка убрано, вместо него меню «1 — ассистент, 0 — оператор» |
| 18.09 | Решение для диалплана записывается до прощальной фразы | Если звонящий положит трубку или упадёт синтез, звонок всё равно уйдёт оператору, а не в тишину |
| 18.09 | Кадры, сказанные поверх бота, переигрываются в детектор речи | Иначе распознавание получало обрывок перебившей фразы (находка аудита №7) |
| 18.09 | Один поток ресемплинга на фразу (`StreamResampler`) | Пересчёт каждого куска отдельно давал щелчки на стыках синтеза |
| 18.09 | `globals_custom.conf` хранится в репозитории | Переменная `EDUVOICE_BRIDGE` жила только на сервере: восстановление «с нуля» дало бы неработающего помощника |
| 18.09 | Служебные фразы синтезируются при старте сервиса | Приветствие начинается мгновенно; заодно ошибка в текстах видна при старте, а не во время звонка |
| 18.09 | Панель заменена на CRM: обращения, граждане, база знаний, аналитика | Звонок — начало работы, а не её конец; журнала звонков для call-центра министерства мало |
| 18.09 | Данные — SQLite (WAL) в одном файле для моста и CRM | Одна машина, нужны транзакции и поиск; проверено на сервере: 3.53.1, WAL, FTS5 |
| 18.09 | CRM — отдельный сервис на FastAPI, порт 9095 | Перезапуск CRM не должен ронять звонки; стек проверен на glibc 2.17 до начала работы |
| 18.09 | Ответы помощника живут в базе, а не в YAML; черновики недоступны боту | Супервайзер правит текст без программиста; неготовая формулировка не попадёт к гражданину |
| 18.09 | Панель не запускается без пароля | Страница показывает записи разговоров граждан: случайная публикация недопустима |
| 18.09 | Панель только читает (`GET`/`HEAD`), остальное отклоняется | Данные звонков нельзя изменить через веб |
| 18.09 | Проект переименован в EduVoice целиком: код, переменные, сервис, пользователь, каталог, контексты диалплана и путь записей | Одно имя везде: проверяющий не должен видеть два названия. Записи старых звонков панель по-прежнему находит |
