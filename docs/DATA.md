# Данные: что система хранит, где и кто это видит

Голос человека — биометрические данные, а расшифровка разговора с министерством — это
персональные данные о его образовании и жизненных обстоятельствах. Поэтому здесь описано
не «какие есть таблицы», а **что именно о гражданине попадает в систему, кто может это
открыть и что с этим будет дальше**.

Схема версии **6**, 13 содержательных таблиц плюс два индекса полнотекстового поиска.
Файл: `/opt/eduvoice/data/eduvoice.db` (SQLite, режим WAL).

---

## 1. Что появляется от одного звонка

Гражданин звонит и спрашивает про стипендию. После разговора в системе оказывается:

| Что | Где | Пример |
|---|---|---|
| Номер, с которого звонили | `contacts.phone`, `calls.caller` | `998901234567` |
| Время, длительность, итог | `calls` | `18.09 22:00`, `30 с`, `ответил помощник` |
| Запись разговора (WAV) | файл на диске, путь в `calls.recording` | `eduvoice/20260918/<uuid>.wav` |
| Расшифровка вопроса и ответа | `turns.question`, `turns.answer` | «Stipendiya qanday olinadi» |
| Откуда взят ответ | `turns.source`, `turns.faq_id` | «59-son qaror, 6-band» |
| Сколько времени заняли этапы | `turns.stt_ms`, `decision_ms`, `total_ms` | `300 / 120 / 863` |
| Метка вопроса в записи | `turns.at_ms` | `9000` — плеер в CRM перематывает сюда |

Карточка гражданина (`contacts`) заводится **автоматически при первом звонке** — по номеру.
Имя, категория (абитуриент, студент, родитель), вуз и заметка появляются только если их
впишет сотрудник.

Дублирующая запись того же самого идёт в `logs/<дата>.jsonl` — на случай, если база
занята. Это резерв, а не второй источник правды.

## 2. Таблицы

```
users              сотрудники: логин, имя, роль, внутренний номер, хэш пароля, активен
contacts           граждане: телефон, имя, категория, вуз, заметка
calls              звонки: время, длительность, итог, причина завершения, запись
turns              реплики: вопрос, ответ, намерение, действие, источник, задержки
tickets            обращения: номер, тема, текст, статус, приоритет, срок, решение
ticket_events      лента обращения: смены статуса, назначения, комментарии
knowledge          ответы помощника: текст, ключевые слова, источник, статус, версия
knowledge_versions история правок ответов: прежний текст и кто его менял
callbacks          обещанные перезвоны: когда, кому, результат
audit              журнал действий сотрудников
settings           внутренние значения (ключ-значение)
lex_documents      нормативные акты: номер, название, ссылка, дата, когда скачан
lex_clauses        пункты актов: текст, номер пункта, якорь для ссылки на lex.uz
turns_fts          полнотекстовый индекс по расшифровкам (FTS5)
lex_fts            полнотекстовый индекс по пунктам актов (FTS5)
```

Связи: `calls.contact_id → contacts`, `turns.call_id → calls`, `tickets.call_id → calls`
(при удалении звонка становится `NULL`), `tickets.contact_id → contacts`,
`ticket_events.ticket_id → tickets`, `knowledge_versions.knowledge_id → knowledge`,
`lex_clauses.document_id → lex_documents` (при удалении акта пункты уходят вместе с ним).

### Тексты законов — не персональные данные

`lex_documents` и `lex_clauses` содержат только официально опубликованные документы,
скачанные с lex.uz командой `make lex-fetch`. Никаких сведений о гражданине там нет, и
эти таблицы можно копировать и показывать свободно. Повторная загрузка **заменяет** акт
целиком: изменённый пункт не должен остаться в базе рядом со своей новой редакцией.

### Итог звонка (`calls.outcome`)

Три значения, и различие между ними важнее, чем кажется:

| Значение | Что означает | Подпись в CRM |
|---|---|---|
| `bot` | помощник дал ответ хотя бы на один вопрос, человек не понадобился | Ответил помощник |
| `operator` | звонок передан живому оператору | Перевод на оператора |
| `dropped` | разговор закончился, не дав ни одного ответа | Без ответа |

Определяется в `store/write.py::outcome_of` по тому, **была ли доставлена хоть одна
реплика с ответом** (`action` = `faq` или `answer` и непустой текст), а не по тому, кто
первым положил трубку. Служебные фразы — «я вас не понял», «перевожу на оператора»,
«до свидания» — тоже создают реплику, поэтому считать их ответами нельзя: иначе звонок,
где гражданин ничего не добился, попал бы в статистику успехов.

Отсюда же берётся главная цифра рабочего стола — **доля решённых без оператора** — это
ровно `outcome = 'bot'`.

## 3. Кто что видит

| Роль | Звонки и граждане | Обращения | Аналитика | База знаний | Администрирование |
|---|---|---|---|---|---|
| Оператор | все | все | ✗ | только чтение | ✗ |
| Супервайзер | все | все | ✓ | правка и публикация | ✗ |
| Администратор | все | все | ✓ | правка и публикация | ✓ |

**Почему оператор видит все звонки, а не только свои.** Он отвечает тому, кто позвонил
сейчас, и должен видеть, о чём этот человек спрашивал раньше — иначе гражданин будет
пересказывать свою историю каждому новому сотруднику. Подотчётность держится не на
запретах, а на журнале: каждый вход, каждое открытие, создание и изменение обращения,
каждая публикация ответа и каждый звонок из CRM попадают в `audit` с указанием логина и
времени. Если министерству понадобится разграничение по отделам — это одно условие в
запросах `crm/repo.py`.

## 4. Защита

- пароли — `hashlib.scrypt` со случайной солью, сравнение через `compare_digest`;
- сессия — cookie, подписанная HMAC, срок 12 часов; деактивация сотрудника действует
  со следующего запроса;
- каждая форма несёт токен, привязанный к сессии; выход — только POST с токеном;
- перебор пароля: пять неудач — минута ожидания для этого логина;
- пароль сотрудника — не короче 8 символов; последнего администратора нельзя лишить прав
  или отключить (иначе систему уже не восстановить без правки базы на сервере);
- имя файла записи проверяется дважды, выйти за каталог записей невозможно (проверено
  тестами на `../../etc/passwd` и его закодированные варианты);
- запрос к базе через `make sql` открывает соединение **только для чтения** средствами
  самого SQLite;
- сервисы работают не от `root`, с `NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome`;
- порты моста (9092 звук, 9093 управление) слушаются только на `127.0.0.1`;
- в репозитории нет ни одного секрета: `.env` в `.gitignore`, вся история коммитов
  просканирована на ключи и пароли.

## 5. Где физически лежит

| Что | Путь | Кто читает |
|---|---|---|
| База | `/opt/eduvoice/data/eduvoice.db` | `eduvoice`, `root` |
| Записи разговоров | `/var/spool/asterisk/monitor/eduvoice/<дата>/<uuid>.wav` | `asterisk`, `root` |
| Журналы звонков | `/opt/eduvoice/app/logs/<дата>.jsonl` | `eduvoice`, `root` |
| Озвученные фразы | `/opt/eduvoice/app/audio/` | `eduvoice`, `root` |
| Секреты | `/root/eduvoice-credentials.txt`, `.env` (права `600`) | только `root` |
| Резервные копии | `/opt/eduvoice/data/backup-<дата>.db` | `eduvoice`, `root` |

Речь обрабатывается сервисом **VoiceLab.uz** — узбекской компанией; звук не покидает
страну. Зарубежные голосовые API сознательно не используются, хотя они дешевле и быстрее
подключаются.

Копия базы делается командой `make backup` — согласованно, прямо во время работы, через
механизм резервного копирования SQLite (не копированием файла).

## 6. Чего сознательно нет

Это хакатон, и следующие вещи не сделаны намеренно — с пониманием, чего они стоят:

- **Срока хранения записей и расшифровок.** Для промышленной эксплуатации его нужно
  согласовать с юристами министерства и автоматически удалять старше срока. Технически —
  одно запланированное задание.
- **HTTPS.** CRM работает во внутренней сети по паролю. В министерстве нужен сертификат.
- **Двухфакторной аутентификации** и разграничения по отделам.
- **Шифрования базы на диске.** Защита сейчас — права файловой системы и то, что сервер
  не выставлен наружу.

Всё перечисленное — решения, а не забытые пункты; они записаны здесь именно для того,
чтобы проверяющий не тратил время на их поиск.
