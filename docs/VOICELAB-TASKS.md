# Задачи: подключение VoiceLab (человек B)

Этот документ самодостаточен: в нём есть контракт, порядок задач, критерии приёмки и
способы проверки. Всё, что нужно от человека A, уже готово и работает — ассистент
принимает звонки и ведёт диалог на заглушках, CRM показывает звонки и расшифровки.
Осталась одна, но главная часть: **настоящий узбекский голос**.

---

## 1. Граница ответственности

**Твоя зона** — один модуль `eduvoice/voicelab.py` (или пакет `eduvoice/voicelab/`) и файлы,
которые он создаёт (аудио-кэш, отчёты с замерами).

**Не трогаем:** телефонию (`asterisk/`), мост (`eduvoice/session.py`, `audio.py`,
`vad.py`, `brain.py`), CRM (`crm/`), базу (`store/`). Если кажется, что нужно поменять
что-то за пределами своей зоны — пиши A, это почти всегда означает, что контракт понят
иначе.

**Единственная точка стыковки** — `eduvoice/interfaces.py`. Мост ждёт три объекта:

```python
def build_voicelab_providers(settings) -> tuple[SpeechToText, TextToSpeech, ChatModel]:
    """Вызывается мостом на каждый звонок, когда EDUVOICE_PROVIDER=voicelab."""
```

Точные сигнатуры (копировать как есть):

```python
class SpeechToText(Protocol):
    async def open(self, language: Language) -> None: ...        # вызывается один раз в начале звонка
    async def transcribe(self, pcm16k: bytes) -> Transcript: ... # одна фраза 0.1–35 с → финальный текст
    async def close(self) -> None: ...

class TextToSpeech(Protocol):
    async def warm_up(self, language: Language) -> None: ...     # открыть соединения заранее
    def stream(self, text: str, language: Language) -> AsyncIterator[bytes]: ...
    async def close(self) -> None: ...

class ChatModel(Protocol):
    async def complete_json(self, messages: list[ChatMessage], timeout_s: float) -> dict: ...
```

Форматы звука зафиксированы и **не обсуждаются** (пересчёт частот делает мост, провайдер
получает и отдаёт ровно это):

| Куда | Формат |
|---|---|
| `transcribe(pcm16k)` получает | PCM s16le, моно, **16 000 Гц**, без заголовка WAV |
| `stream()` отдаёт | PCM s16le, моно, **24 000 Гц**, кусками по мере генерации |

Язык один: `"uz"`.

## 2. Что мост делает с твоими объектами (важно для дизайна)

1. В начале звонка: `await stt.open("uz")` и `await tts.warm_up("uz")`. Если любой из них
   бросит исключение — звонок сразу уходит оператору. Значит, `warm_up` должен быть
   быстрым и не падать из-за мелочей.
2. На каждую фразу звонящего: `await stt.transcribe(pcm)` под таймаутом **5 секунд**.
   За звонок таких вызовов до восьми — **одно соединение должно переживать несколько
   фраз** (или ты держишь пул, см. вопрос Q1).
3. Ответ: мост итерирует `stream()` и отдаёт звук в трубку. **Первый кусок должен прийти
   быстро** — на него стоит таймаут 3 секунды.
4. Перебивание: когда человек заговорил поверх ответа, мост **закрывает итератор**
   (`aclose()`). Твой код обязан в этот момент остановить синтез (`{"action":"interrupt"}`),
   иначе платим за звук, который никто не услышит.
5. В конце звонка: `await stt.close()` и `await tts.close()`.
6. Любая ошибка провайдера должна прийти как `SttError` / `TtsError` / `LlmError`
   (из `eduvoice.interfaces`). Мост поймает её и переведёт звонок на человека. Никаких
   «голых» исключений наружу.

## 3. Как работать, не имея под рукой ни сервера, ни телефона

```bash
make install                       # окружение (Python 3.12, uv)
make check                         # линтер + типы + 103 теста — должно быть зелено до начала
uv run pytest tests/ -q -k fake    # как выглядит эталонное поведение заглушек
```

Смотри `eduvoice/fakes.py` — это работающая реализация тех же трёх интерфейсов.
Твоя задача — сделать то же самое, но через VoiceLab.

Сделай себе CLI (задача V1), чтобы всё проверялось без телефонии:

```bash
uv run python -m eduvoice.voicelab.cli ping                 # ключ жив, список голосов
uv run python -m eduvoice.voicelab.cli stt sample.wav       # файл → текст + задержка
uv run python -m eduvoice.voicelab.cli tts "Assalomu alaykum" out.wav
uv run python -m eduvoice.voicelab.cli bench recordings/    # таблица задержек
```

## 4. Что известно про API (из документации, проверить в V0)

| Тема | Что записано |
|---|---|
| Адрес | `https://api.voicelab.uz`, WebSocket `wss://api.voicelab.uz/...` |
| REST-авторизация | `Authorization: Bearer vlk_<ключ>` |
| WebSocket-авторизация | серверным клиентам — заголовок `xvl-api-key`; браузерам — тикет `POST /v1/ticket`. **Ключ в URL не передавать** |
| STT realtime | `wss://…/v1/stt/stream`: `{"type":"start","language":"uz","audio_format":"pcm_s16le","sample_rate":16000,"channels":1}` → бинарные кадры → `{"type":"commit"}` → `{"event":"final","text":…}` |
| STT ограничения | один commit — **0,1–35 с**, промежуточных результатов **нет** |
| STT REST | `POST /v1/stt` multipart, обязателен заголовок `Idempotency-Key` |
| TTS realtime | `wss://…/v1/tts/stream`: `{"text":…,"language":"uz","voice_id":…,"speed":1}` → кадры PCM 24 кГц → `{"event":"done"}`; отмена `{"action":"interrupt"}` |
| TTS ограничение | **один текст на одно соединение** → нужен пул заранее открытых соединений |
| TTS REST | `POST /v1/tts`, текст 1–1000 байт → WAV 24 кГц |
| LLM | `POST /v1/chat/completions` (формат как у OpenAI), **2 одновременные генерации на аккаунт** |
| Ошибки | 402 — нет кредитов, 429 — ждать `Retry-After`, 500 — повтор с тем же `Idempotency-Key`; 401/403/404/422 не повторять |

Всё из этой таблицы считается **гипотезой**, пока не проверено твоими руками в V0.

## 5. Задачи

Порядок важен: V0–V5 — то, без чего демо не состоится; V6–V9 — качество и скорость;
V10–V13 — надёжность и отчёты.

### Обязательные

| # | Задача | Оценка | Критерий приёмки |
|---|---|---|---|
| **V0** | **Ответить на открытые вопросы** (раздел 6) маленькими скриптами. От ответов зависит устройство модуля, поэтому это первое, что делается | 2 ч | `docs/voicelab-findings.md` с таблицей «вопрос → ответ → чем проверено» |
| **V1** | Каркас модуля и CLI: `ping`, `stt`, `tts`, `bench`. Ключ из `.env` (`VOICELAB_API_KEY`), голос — `VOICELAB_VOICE_UZ` | 2 ч | `cli ping` печатает список узбекских голосов и остаток кредитов |
| **V2** | `VoiceLabSpeechToText`: соединение открывается в `open()`, переживает несколько фраз за звонок (или пул, если Q1 = «нет»), `transcribe()` возвращает `Transcript(text, language, duration_ms, latency_ms)` | 4 ч | На 5 записанных фразах: текст верный, `latency_ms` заполнен; повторный вызов в том же звонке работает |
| **V3** | `VoiceLabTextToSpeech`: пул из 2 открытых соединений, `stream()` отдаёт куски сразу же, `aclose()` шлёт `interrupt`, пул пополняется в фоне | 5 ч | Время до первого куска измерено; закрытие итератора останавливает синтез ≤ 200 мс (видно в логе VoiceLab по `duration_ms`) |
| **V4** | Выбор голоса: перебрать узбекские голоса, выбрать по разборчивости на телефонном канале (8 кГц!), подобрать скорость 0,9–1,1 | 2 ч | `VOICELAB_VOICE_UZ` зафиксирован, в отчёте — почему этот |
| **V5** | Отображение ошибок: любые сбои → `SttError` / `TtsError` / `LlmError`, в логе остаётся `request_id`. Таймауты: STT 5 с, первый кусок TTS 3 с | 3 ч | Тесты с неверным ключом, с обрывом сети и с 429: мост не падает, звонок уходит оператору |

### Качество и скорость

| # | Задача | Оценка | Критерий приёмки |
|---|---|---|---|
| **V6** | **Кэш синтеза на диске**: ключ — `sha256(текст + голос + скорость)`, значение — PCM 24 кГц. Попадание в кэш = мгновенный ответ. Так автоматически ускоряются и служебные фразы, и ответы из базы знаний | 3 ч | Повторный `stream()` того же текста отдаёт первый кусок < 50 мс; файлы лежат в `audio/tts-cache/` |
| **V7** | **Прогрев кэша**: CLI `prewarm`, который берёт служебные фразы из `content/prompts.yaml` и **опубликованные ответы из базы** (таблица `knowledge`, `status='published'`) и синтезирует всё заранее | 2 ч | После `cli prewarm` первый ответ на частый вопрос звучит без задержки синтеза |
| **V8** | **Нормализация текста перед синтезом**: числа, даты, суммы, аббревиатуры (OTM, BMBA, «2026-yil», «10-band») — как их писать, чтобы голос читал правильно | 3 ч | Список правил + функция `normalize_uz(text)` + тесты на 15 примерах |
| **V9** | **Замеры на телефонном звуке**: 20 фраз, записанных через софтфон и MixMonitor (8 кГц, шум линии), поднятых до 16 кГц. Считаем p50/p95 задержки STT, долю ошибок в словах, время до первого звука TTS | 3 ч | `docs/voicelab-benchmark.md`: таблица + честный вывод «укладываемся в бюджет / нет» |

### Модель и надёжность

| # | Задача | Оценка | Критерий приёмки |
|---|---|---|---|
| **V10** | **LLM**: прогнать 20 тестовых вопросов через `POST /v1/chat/completions` с промптом из `eduvoice/brain.py`, режим «только JSON». Сравнить с одной внешней моделью по качеству узбекского и задержке | 3 ч | Рекомендация с цифрами: берём VoiceLab или нет |
| **V11** | `VoiceLabChatModel` (если V10 за VoiceLab): `complete_json` возвращает **словарь**, а не текст; семафор на **2 одновременные генерации**; при мусоре вместо JSON — `LlmError` | 3 ч | Тест: 5 параллельных вызовов не нарушают лимит; ответ-не-JSON превращается в `LlmError` |
| **V12** | **Устойчивость к лимитам**: 429 → ждать `Retry-After`, 402 → понятная ошибка в лог и перевод на оператора, 500 → один повтор с тем же `Idempotency-Key` | 2 ч | Тест с подменённым сервером (локальная заглушка отвечает 429/402/500) |
| **V13** | **Сдача**: `EDUVOICE_PROVIDER=voicelab` на сервере, три живых звонка (вопрос из базы знаний, просьба оператора, прощание), задержки видны в CRM | 2 ч | В CRM у звонка видны `распознавание`, `решение`, `всего`; запись слушается; текст совпадает со сказанным |

**Итого: ≈ 39 часов.** Минимум для демо — V0–V5 (≈ 18 часов): этого достаточно, чтобы
ассистент заговорил по-настоящему.

## 6. Открытые вопросы (задача V0)

От ответов зависит устройство модуля — поэтому сначала они, потом код.

1. **Можно ли в одном STT-соединении сделать несколько `commit` подряд** (фраза → текст →
   следующая фраза)? Если нет — нужен пул соединений, как у TTS.
2. **Работает ли заголовок `xvl-api-key` для STT WebSocket**, или обязателен тикет?
3. **Через сколько секунд простоя** VoiceLab закрывает открытое, но неиспользуемое
   соединение? (От этого зависит, как часто пополнять пул.)
4. **Сколько одновременных WebSocket-соединений** разрешено на ключ? Хватит ли на
   3 звонка × (1 STT + 2 TTS) = 9?
5. **Насколько хуже распознаётся звук, поднятый с 8 кГц до 16 кГц**, по сравнению с
   настоящими 16 кГц? (Одна и та же фраза, два файла, сравнить текст.)
6. **Сколько кредитов** стоит минута распознавания, минута синтеза и один звонок целиком?
7. **REST TTS отдаёт сам WAV или ссылку** на него?
8. **Есть ли у STT режим, где можно слать звук потоком и получать финал раньше**, чем
   через commit (например, по тишине на стороне VoiceLab)?

## 7. Как проверять свою работу

### Локально, по файлам

```bash
uv run python -m eduvoice.voicelab.cli stt recordings/savol-01.wav
uv run python -m eduvoice.voicelab.cli tts "Stipendiya qanday olinadi" out.wav
uv run python -m eduvoice.voicelab.cli bench recordings/
```

### На сервере, живым звонком

```bash
# переключить мост на VoiceLab
ssh root@10.103.10.86 "cd /opt/eduvoice/app && sed -i 's/^EDUVOICE_PROVIDER=.*/EDUVOICE_PROVIDER=voicelab/' .env"
make restart
make call-test          # Asterisk сам звонит ассистенту
make logs               # видно: heard '…', decision=…, задержки
```

### В CRM — самое удобное

`http://10.103.10.86:9095` → **Звонки** → открыть звонок. Там видно:

- что именно распознала твоя реализация (текст вопроса);
- что ответил ассистент;
- **задержки по этапам**: распознавание, решение, всего;
- запись разговора с метками — можно послушать, совпадает ли текст с голосом.

Это и есть твой главный измерительный прибор: после V13 в CRM должны появиться
настоящие узбекские фразы вместо заглушечных.

## 9. Грабли, на которые легко наступить

- **Не пересчитывай частоты внутри провайдера.** Мост даёт 16 кГц и ждёт 24 кГц. Любой
  «умный» ресемплинг внутри модуля ломает и звук, и замеры.
- **Не возвращай WAV.** `stream()` отдаёт сырой PCM без заголовка; заголовок в середине
  потока звучит как щелчок.
- **Пустая речь — не ошибка.** `no_speech_detected` → `Transcript(text="")`, мост сам
  переспросит. Исключение здесь означало бы перевод на оператора без причины.
- **35 секунд — предел одного commit.** Мост режет фразы по 30 с, но проверь границу.
- **Перебивание должно останавливать синтез.** Иначе кредиты тратятся впустую и следующий
  ответ начинается с хвоста предыдущего.
- **Ключ — только в `.env` на сервере.** В репозиторий не коммитим ничего секретного;
  `.env` в `.gitignore`.
- **Логируй `request_id`** каждого запроса: без него поддержка VoiceLab не сможет помочь.
